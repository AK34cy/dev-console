# Managed Servers

A Managed Server is a Linux server that Dev Console can reach over SSH. Projects use Managed Servers for infrastructure setup, Preview deployment, and Production promotion.

## Server Fields

- Server ID: stable internal identifier.
- Display name: human-readable name.
- Hostname / IP: SSH target.
- SSH port: usually `22`.
- SSH username: the Linux user Dev Console will use for remote management and deployment.
- Dev Console Server Key: the shared SSH key generated by Dev Console.
- Description: optional note.

## SSH Onboarding

1. Log in as the SSH user Dev Console will use.
2. Copy and run the generated setup command.
3. Enter the user's sudo password if prompted.
4. Add or save the server in Dev Console.
5. Press Test Connection.

The setup command installs the Dev Console public key for the configured SSH user and prepares passwordless sudo for v1 remote management.

Root SSH is not required. If the configured SSH user is root, Dev Console can run privileged operations directly. Otherwise Dev Console uses `sudo -n`.

## Select/Edit

Use Select/Edit on a server card to:

- select that server for the onboarding setup command
- open the existing Edit Server form
- update the command as the SSH username changes

Selecting a server does not save or change server configuration by itself.

## Test Connection

Test Connection verifies SSH access and records:

- Reachable or Unreachable status
- hostname
- operating system when available
- remote user
- working directory
- response time
- passwordless sudo readiness

## Remove

Remove deletes only the server registration from Dev Console. It does not delete SSH keys, users, remote files, Apache configuration, or project data.
